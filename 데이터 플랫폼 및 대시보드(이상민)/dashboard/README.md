# dashboard — Streamlit 관제 대시보드

프로젝트 전체 배경과 실행 순서는 최상위 [`../README.md`](../README.md)를 참고하세요.

## 파일 구성

| 파일 | 설명 |
|---|---|
| `smart_factory_dashboard_v3.py` | Streamlit 관제 대시보드 본체 (DB 조회 + 젯슨 영상 + SLAM 미니맵 + AI 대응안) |

파일명은 `v3`이지만 내용은 v11입니다. 상단 주석에 v1~v11 개선 이력이 남아 있습니다.

DB를 못 읽을 때는 위 배너 자리에 회색 `📡 상태 불명 — 데이터베이스 응답 없음` 배너가
뜨고 구역 카드가 전부 "상태 불명"이 됩니다. 빨강(위험)·주황(로봇 미연결)·회색(관제
시스템이 눈이 먼 상태)은 대응해야 할 대상이 서로 다르므로 색으로 구분합니다.

사이드바에서 **화면 구성 = 관제 집중**을 고르면 상세 조회를 접고 미니맵을 400px로
낮춰서, 영상과 지도가 1080p 한 화면에 같이 들어옵니다. 폭은 그대로 전체를 쓰므로
미니맵이 좁은 화면용 레이아웃으로 접히지 않습니다.

```
관제 집중:  경보/카드/상태바 → [영상 | AI 권장 조치] → 지도(400px)   (끝)
```

**크게 보기**는 둘 중 하나를 본문 전체에 띄웁니다. 확대 중에도 **경보와 구역 카드는
그대로 남습니다** — 영상을 크게 보려고 눌렀다가 그 사이 난 위험을 놓치면 확대 기능이
사고 원인이 됩니다.

```
크게 보기:  경보/카드/상태바 → [✖ 닫기] → 영상 또는 지도 (전체 폭)   (끝)
```

**AI 대응안 기록**도 같은 방식으로 들어갑니다. 패널의 `🗂 이전 기록 보기`를 누르면
`?expand=plans`로 전환되고, 거기서 기간(1시간 / 24시간 / 전체 기록)과 구역을 골라
최대 200건을 봅니다.

```
대응안 기록:  경보/카드/상태바 → 🗂 AI 대응안 기록 [✖ 닫기]
              구역 (전체|A|B|C)   기간 (1시간|24시간|전체)
              ┌──────────────────────────────┐  [⬇️ CSV]
              └──────────────────────────────┘
```

### v6에서 무엇이 어떻게 바뀌었나

v6까지의 배치는 `제목 → [영상|미니맵] → 메트릭 4개 → 구역 카드`, 사이드바에 `IP 입력 +
상세 로그 표`였습니다. 관제 화면으로서 문제가 6가지 있었고 전부 고쳤습니다.

**1. 경보가 화면 아래에 있었습니다.**
제목(80px) + 영상 블록(520px + 캡션) 약 700px를 지나야 "위험 몇 건"이 나왔습니다.
1080p 모니터에서 겨우 걸치고, 노트북(768p)에서는 구역 카드가 아예 스크롤해야 보였습니다.
지금은 `경보 배너 → 구역 카드 → 영상` 순서입니다.

**2. 미니맵이 항상 좁은 화면용 레이아웃으로 떴습니다.**
`minimap_web.html`은 폭 900px 아래에서 탐지 목록을 지도 밑으로 내리도록 만들어져 있습니다.

```css
.stage{grid-template-columns:1fr 296px}          /* 지도 | 탐지목록 */
@media (max-width:900px){ .stage{grid-template-columns:1fr}  .side{max-height:44vh} }
```

그런데 `st.columns(2)` 안에서는 1920px 모니터에서도 사이드바·여백을 빼면 약 745px밖에
안 됐습니다. **즉 대시보드 안에서 한 번도 설계대로 뜬 적이 없었고**, 520px 높이 중 지도에
남는 건 300px 남짓이었습니다. 이제 미니맵은 `render_minimap()`으로 본문 한 줄을 씁니다.

**3. 상세 로그가 300px 사이드바에 6열로 들어갔습니다.**
`시간 / 객체명 / 거리 / 카메라 내 위치 / 위험도 / 사유` — 한글 문장이 들어가는 '사유'
열까지 열당 50px이었습니다. 본문으로 옮겨 전체 폭을 주고, 사이드바에는 설정만 남겼습니다.

**4. 위험 표시가 약했습니다.**
정상·주의는 옅은 배경 + 진한 글씨인데, **위험만 진한 빨강 배경 + 흰 글씨로 반전**됩니다.
색상 이름이 아니라 명암 관계가 달라지므로 색각 이상이 있어도, 멀리서 봐도 구분됩니다.
여기에 위험이 있을 때만 상단 배너가 추가로 나타납니다 — 항상 떠 있는 경고는 곧 배경이
되어 아무도 보지 않기 때문입니다. 애니메이션은 `prefers-reduced-motion`을 존중합니다.

**5. 죽은 메트릭이 가장 좋은 자리를 썼습니다.**
"전체 구역 3개"는 상수인데 첫 칸이었고, "정상 구역 수"·"미연결 로봇 수"는 바로 아래
구역 카드와 중복이었습니다. 메트릭 4칸(약 140px)을 상태 바 한 줄(약 40px)로 줄였습니다.

**6. `response_plans`가 화면에 없었습니다(v6의 알려진 이슈).**
`RagResponseAgent`가 만든 대응안이 DB에만 쌓이고 어디에도 안 나왔습니다. 이제 영상 옆에
최신 1건을 크게, 아래 탭에서 전체 이력을 보여줍니다. **해결됨.**

### v8에서 무엇이 어떻게 바뀌었나

v7까지의 문제는 배치가 아니라 **데이터가 화면에 도달하는 방식**이었습니다.

**1. 상세 감지 로그가 사실상 "최근 1초"였습니다.**
`ResponsePlanThrottle`은 `response_plans`에만 걸리고 `patrol_logs` 적재는 억제하지
않습니다([`../pipeline/patrol_pipeline_rag.py`](../pipeline/patrol_pipeline_rag.py) 상단
주석에 명시). 젯슨이 30fps로 넣으면 `LIMIT 30`은 1초치입니다. **시각을 0.1초 단위까지
찍고 있었던 것 자체가 그 증거였습니다.** 관제 담당자가 "아까 그거 뭐였지"를 확인할 수
없다는 뜻이라, 그 패널의 존재 이유가 없었습니다.

이제 최근 `DETAIL_SCAN_ROWS`(2000행 ≈ 60초)를 훑어 **연속된 같은 (구역, 객체, 위험도)
구간을 한 줄로 접습니다.**

| 기간 | 지속 | 건수 | 구역 | 객체명 | 위험도 | 최근접 | 사유 |
|---|---|---|---|---|---|---|---|
| 14:32:07 ~ 14:31:59 | 8.0초 | 241 | B | 지게차 | 🔴 위험 | 1.24 m | 지게차 근접 위험 (1.24m) |
| 14:31:58 ~ 14:31:37 | 21.0초 | 630 | A | 작업자 | 🟢 정상 | 측정불가 | - |

프레임 단위로 봐야 할 때를 위해 **원본 로그** 보기를 따로 남겼습니다.

**2. 화면에서 제일 중요한 영역에만 예외 처리가 없었습니다.**
대응안 패널은 `try`로 감싸져 있는데 정작 경보·구역 카드를 그리는
`_render_status()`는 아니어서, DB가 잠깐 끊기면 **화면 맨 위(경보가 있어야 할 자리)가
빨간 파이썬 트레이스백**으로 바뀌었습니다. 관제 화면에서 "정보 없음"을 "이상 없음"처럼
보이게 두는 것도, 트레이스백을 띄우는 것도 둘 다 사고로 이어집니다. 이제 회색
"상태 불명" 배너와 카드를 그립니다. 커넥션 캐시는 `get_cursor()`가 비우므로 DB가
살아나면 다음 틱에 저절로 복구됩니다.

**3. `JETSON_IP`/`DAEUN_LAPTOP_IP` 환경변수가 죽어 있었습니다.**
사이드바 기본값이 `"localhost"` 고정이었고, 받는 쪽은 `jetson_ip or JETSON_IP`라서
`"localhost"`(truthy)에서 fallback으로 넘어갈 일이 없었습니다. **즉 환경변수를 설정해도
아무 일도 일어나지 않았습니다.** 시연 때마다 IP를 손으로 치게 만들던 원인입니다.
이제 사이드바 기본값 자체를 환경변수에서 읽습니다.

**4. 로봇이 죽어도 조용했습니다.**
`위험`은 배너 + 반전 + 펄스로 3중 강조인데 `미연결`은 회색 점선 카드 하나뿐이었습니다.
순찰 로봇이 응답하지 않는 것은 위험 감지만큼 즉각 대응이 필요한데 시각적 우선순위가
정반대였고, 자리를 비운 사이 조용히 회색으로 바뀌고 끝이었습니다. 이제 주황 배너가
붙고, **오다가 끊긴 구역**(로봇·네트워크 장애)과 **한 번도 안 온 구역**(아직 안 켰거나
구역 설정이 틀림)을 문구로 나눕니다.

**5. `주의`가 상태 바에서 증발했습니다.**
상태 바가 위험/정상/미연결만 세어서, 세 구역이 전부 `주의`면 `위험 0 · 정상 0/3 ·
미연결 0`이 되고 세 구역이 어디로 갔는지 설명이 없었습니다(네 숫자의 합이 구역 수와
안 맞음). `🟡 주의` 칸을 추가했습니다.

**함께 정리한 것**

- `ZONES`/`TOTAL_ZONES`가 `common/schema.py`의 `DEFAULT_ZONES`를 복제하고 있었습니다.
  그 파일이 존재하는 이유가 바로 이 drift를 막기 위해서인데 대시보드만 예외였습니다.
  이제 import해서 씁니다 — 구역을 늘리면 대시보드도 따라옵니다.
- AI 권장 조치 카드에 날짜가 없어서 **어제 14:32의 대응안이 5분 전 것과 똑같이 빨간
  테두리**로 떠 있었습니다. 상황이 끝난 뒤에도 화면은 계속 경보 상태로 보였습니다.
  이제 상대 시각(`12초 전`, `2시간 전`)을 붙이고, `PLAN_FRESH_SECONDS`(5분)를 넘으면
  경보색을 빼고 "지난 대응안"이라고 명시합니다.
- **대응안 이력을 볼 때 구역 라디오가 눌리기만 하고 표는 안 바뀌었습니다**
  (`fetch_plans`가 `zone`을 안 봤습니다). 눌러도 안 바뀌면 사용자는 화면이 멈춘 걸로
  오해합니다. 이제 세 보기 모두 구역 선택을 따르고, `전체` 선택지가 생겼습니다.
- 30줄짜리 흑백 표에서 `위험` 행을 눈으로 찾아야 했습니다. 위험도에 🔴/🟡/🟢를 붙이고
  행 배경도 칠합니다(Styler를 못 쓰는 환경이면 이모지만 남습니다).
- `NULL`이 표에 `NaN`/`nan%`로 새어나오던 것을 `-`로 정리했습니다.

### v9에서 무엇이 어떻게 바뀌었나

v8까지는 **정보가 정확하게 표시되는 것**까지만 봤습니다. 관제석에 앉혀 보면 남는
문제는 "그래서 사람이 무엇을 하느냐"였습니다.

**1. 경보에 소리가 없었습니다.**
시각 경보만으로는 그 순간 화면을 보고 있는 사람이 필요합니다. 순찰 로봇은 사람이
없는 시간대를 위해 도는 것이라 전제가 뒤집혀 있었습니다. 사이드바의 **소리 경보**를
켜면 새 위험이 들어올 때만 0.72초짜리 경보음이 한 번 납니다.

- **음원 파일을 저장소에 넣지 않습니다.** `wave`/`struct`로 880Hz·660Hz 두 음을
  코드에서 굽습니다(약 4ms, 30KB, 1회 생성 후 캐시). 폐쇄망이나 저장소를 일부만
  받은 상태에서도 소리가 나야 하고, 바이너리는 리뷰가 안 되기 때문입니다 —
  `edge_video`의 자리표시자 SVG와 같은 원칙입니다.
- **기본값은 꺼짐**입니다. 브라우저 자동재생 정책상 사용자가 페이지를 한 번
  건드려야 소리가 나는데, 체크박스를 켜는 동작이 바로 그 조건을 만족시킵니다.
- `st.markdown`으로는 안 됩니다(Streamlit이 `<audio>`를 걸러냅니다).
  `st.audio(autoplay=True)`는 1.37부터라 requirements 하한(1.33)과 안 맞고 플레이어가
  보입니다. `components.html`을 `height=0`으로 씁니다.
- **소리 길이는 `REFRESH_STATUS_SECONDS`(1초)보다 짧아야 합니다.** `components.html`이
  이 조각의 출력이라, 다음 갱신에서 조각이 다시 그려지면 `<audio>`가 사라지며 재생도
  끊깁니다. 소리를 늘리려면 상태 갱신 주기도 같이 늘려야 합니다.

**2. 경보를 확인(acknowledge)할 방법이 없었습니다.**
마지막 위험 로그로부터 5분간, 담당자가 이미 조치했든 말든 배너가 계속 떠 있었습니다.
계속 울리는 경보는 곧 무시하는 경보가 됩니다. 이제 배너 옆에 **✅ 확인**이 있습니다.

- 누르면 그 시점의 위험 로그 `id`를 `ack_danger_id`에 기록하고, 그보다 큰 id가
  들어올 때까지 배너와 소리를 멈춥니다. **새 위험이 오면 다시 뜹니다.**
- **구역 카드의 빨강은 그대로 둡니다.** 확인은 "봤다"이지 "해결됐다"가 아닙니다.
  배너 자리에는 `✅ 위험 확인됨 — 최근 5분 위험 N건` 한 줄이 남아서, 교대 인수인계
  때 지금 무슨 상태인지가 화면에 보입니다.
- 시각이 아니라 `id`를 기준으로 씁니다. `SERIAL`이라 단조 증가가 보장되고, 같은
  `log_time`에 여러 건이 들어와도 하나로 뭉개지지 않습니다.
- **`on_click` 콜백으로 처리하는 것이 중요합니다.** `if st.button(...)`의 반환값으로
  처리하면 그 시점에는 배너가 이미 그려진 뒤라 다음 틱(1초)까지 배너가 남습니다.
  콜백은 Streamlit이 재실행 *전에* 돌리므로 눌린 직후의 그리기에서 이미 사라집니다.

**3. 영상과 지도를 동시에 볼 수 없었습니다.**
미니맵에 전체 폭을 준 v5 판단은 맞지만, 그 대가로 1080p에서 둘이 같은 화면에 안
들어옵니다. 순찰 관제에서 "지금 뭐가 보이나"와 "로봇이 어디 있나"는 같이 봐야 하는
짝입니다. 사이드바 **화면 구성 → 관제 집중**이 상세 조회를 접고 미니맵을 400px로
낮춥니다. **폭은 절대 줄이지 않습니다** — 900px 밑으로 내려가면 미니맵이 좁은 화면용
레이아웃으로 접혀서, 낮춘 높이와 겹쳐 지도가 거의 안 남습니다.

**4. 조회 범위가 고정이었습니다.**
v8의 감지 요약은 최근 2000행(30fps 기준 약 1분)만 훑었습니다. "아까 그거"가 3분
전이면 여전히 안 보입니다. 이제 **1분 / 5분 / 30분**을 고릅니다(기본 5분).

| 범위 | 스캔 상한 | 갱신 주기 |
|---|---|---|
| 최근 1분 | 2,000행 | 2.0초 |
| 최근 5분 | 8,000행 | 3.0초 |
| 최근 30분 | 20,000행 | 6.0초 |

넓은 범위일수록 갱신을 늦춥니다. 30분치를 보고 있다는 것은 지금 흐르는 상황이 아니라
지나간 일을 읽고 있다는 뜻이라 1초 단위 갱신이 필요 없고, 그래야 DB 부하가 범위에
비례해서 늘지 않습니다. **시간(`WHERE`)과 행 수(`LIMIT`) 두 가지로 함께 자릅니다** —
시간은 화면에 적힌 "최근 N분"을 정직하게 만들고, 행 수는 트래픽이 몰려도 집계량이
폭발하지 않게 막습니다. 하나만으로는 정직하거나 안전하거나 하나만 됩니다.

**5. 표를 밖으로 꺼낼 수 없었습니다.**
주간 보고나 발표자료에 넣으려면 화면을 캡처하는 수밖에 없었습니다. 표마다
**⬇️ CSV 내려받기**가 붙습니다.

- **인코딩은 `utf-8-sig`입니다.** 그냥 `utf-8`로 주면 Excel이 BOM이 없다는 이유로
  시스템 코드페이지(한국어 Windows는 cp949)로 열어서 한글이 전부 깨집니다. 예외가
  나지 않아 열어보기 전엔 모르는 종류라, `test_dashboard_tables.py`가 바이트가
  `\xef\xbb\xbf`로 시작하는지 직접 확인합니다.
- **화면에 보이는 프레임을 그대로** 내보냅니다. 원본 컬럼명(`detected_object`)이
  아니라 한글 헤더(`객체명`)가, 원시 float이 아니라 `1.24 m`가 들어갑니다. 표에서
  본 것과 파일이 다르면 그게 더 헷갈립니다.
- 파일명에 표 종류·구역·시각이 들어갑니다(`감지요약_B_20260825_143207.csv`).

### v10에서 무엇이 어떻게 바뀌었나

**영상과 지도를 크게 볼 수 없었습니다.**
1080p에서 영상은 좌측 5/12 칸이라 약 600px, 지도는 560px 높이입니다. 화면에 무엇이
잡혔는지 확인하려면 부족해서, 결국 브라우저로 젯슨 주소(`http://젯슨IP:8500/`)를 따로
열어보게 됩니다. 이제 둘 중 하나를 본문 전체에 띄울 수 있습니다.

**1. 조작 방식이 둘로 갈립니다 — 이게 설계의 핵심입니다.**

| | 확대 방법 | 이유 |
|---|---|---|
| 젯슨 영상 | **그림을 직접 클릭** (+ `⛶ 크게` 버튼) | MJPEG은 자체 조작이 없는 정지영상 스트림이라 클릭을 가져가도 뺏기는 기능이 없음 |
| SLAM 지도 | **`⛶ 크게` 버튼만** | iframe 안의 클릭은 `minimap_web.html` 자신의 확대/이동/탐지목록 조작 — 링크로 감싸면 미니맵을 못 쓰게 됨 |

지도를 클릭으로 확대하게 만들면 v4에서 MJPEG을 버리고 조작 가능한 페이지로 바꾼
이유가 통째로 사라집니다. 그래서 지도만 버튼입니다.

**2. 상태를 `session_state`가 아니라 쿼리 파라미터에 둡니다.**
HTML `<img>`는 Streamlit 위젯이 아니라서 `session_state`를 건드릴 방법이 없습니다.
`<a href="?expand=video" target="_self">`로 감싸면 브라우저가 주소를 바꾸고 Streamlit이
`st.query_params`로 읽습니다. 둘 중 하나를 진실로 정해야 하므로 쿼리 파라미터로
통일했습니다 — 주소창만 봐도 지금 무엇이 확대돼 있는지 드러나고, 그 주소를 그대로
공유할 수도 있습니다. 모르는 값(`?expand=xyz`)은 무시하고 평소 화면을 그립니다.

`target="_self"`가 없으면 Streamlit이 새 탭에서 엽니다.

**3. 확대 중에도 경보와 구역 카드는 그대로입니다.**
접히는 것은 반대쪽 패널과 상세 조회뿐입니다. 관제 화면에 경보를 가리는 모드가 있으면
안 됩니다.

**4. 클릭이 막혀도 기능이 죽지 않습니다.**
Streamlit의 HTML 정화기가 버전에 따라 `<a>`의 속성을 어떻게 다루는지에 기대고 싶지
않았습니다. 제목 옆 `⛶ 크게` 버튼은 순수 Streamlit 위젯이라 어떤 버전에서도 동작합니다.

**5. 확대 시 크기**
- 영상: 폭 100% + `max-height:78vh; object-fit:contain`. 세로가 화면을 넘지 않게
  자르되 잘리지 않고 축소됩니다. 이게 없으면 세로로 긴 화면에서 영상이 화면 밖까지
  늘어나 오히려 덜 보입니다.
- 지도: `MINIMAP_EXPANDED_HEIGHT`(기본 820px). `components.iframe`은 px만 받고
  파이썬은 브라우저 창 높이를 모르므로 `vh`로 줄 수가 없습니다. 노트북(768p)에서
  스크롤이 길면 이 환경변수를 낮추세요.

### v11에서 무엇이 어떻게 바뀌었나

**1. 대응안 패널이 최신 1건만 보여줬습니다.**
대응안은 (구역, 객체)마다 따로 나오므로, 두 구역에서 동시에 뭔가 벌어지면 한쪽이
화면에서 통째로 사라집니다. 이제 첫 건을 크게, 나머지 두 건을 한 줄씩 보여줍니다
(`PLAN_PANEL_LIMIT=3`).

요약 줄에는 **권장 조치 문장을 넣지 않습니다.** 세 줄이 다 문장이면 어느 것이 지금
중요한지 눈으로 못 고릅니다. "어디서 무엇이"까지만 보여주고 자세한 내용은 기록
화면에서 봅니다. 색띠는 위험(빨강)·주의(주황)로 구분하되, `PLAN_FRESH_SECONDS`를
넘긴 것은 등급과 무관하게 회색입니다.

**2. 첫 칸에 무엇을 둘지 — 최신순도 심각도순도 아닙니다.**

| 방식 | 문제 |
|---|---|
| 최신순만 | 방금 들어온 '주의' 3건이 4분 전 '위험'을 밀어냄 |
| 심각도순만 | 3시간 전 '위험' 하나가 자리를 영원히 차지 (v8에서 고친 문제가 부활) |

그래서 **신선한 것 안에서만** 심각도로 줄을 세웁니다.

```sql
ORDER BY CASE WHEN created_at >= LOCALTIMESTAMP - (%s * INTERVAL '1 second')
              THEN CASE risk_level WHEN '위험' THEN 2 WHEN '주의' THEN 1 ELSE 0 END
              ELSE -1 END DESC,
         created_at DESC
```

오래된 것끼리는 전부 `-1`이라 뒤의 `created_at DESC`로 최신순이 됩니다. 즉 최근
5분에 아무 일도 없었으면 v10과 똑같이 "가장 최근 대응안"이 위에 옵니다.

```
신선 위험 4분전 → 신선 주의 10초전 → 신선 정상 5초전
              → 오래된 주의 20분전 → 오래된 위험 3시간전
```

**3. 이전 기록은 "들어가는" 화면으로 뺐습니다.**
패널의 `🗂 이전 기록 보기` → `?expand=plans`(v10 크게 보기와 같은 방식).

| | 상세 조회 (patrol_logs) | 대응안 기록 (response_plans) |
|---|---|---|
| 기간 | 1분 / 5분 / 30분 | 1시간 / 24시간 / **전체 기록** |
| 최대 | 30행(요약) / 60행(원본) | 200건 |
| 자동 갱신 | 2~6초 | **없음** |

기간 선택지가 다른 이유는 대상 테이블이 다르기 때문입니다. `patrol_logs`는 30fps로
쌓여서 '전체'를 열어줄 수 없지만, `response_plans`는 `ResponsePlanThrottle`이 걸려
있어(같은 구역·객체는 30초에 1건) 전체를 훑어도 안전합니다. 자동 갱신을 안 거는 것도
같은 맥락 — 지나간 기록을 읽는 화면이라 몇 초마다 표가 다시 그려지면 읽던 위치만
잃습니다.

**4. 상세 조회에서 "AI 대응안 이력" 탭을 뺐습니다.**
같은 것을 보는 곳이 두 군데면 어느 쪽이 최신인지 매번 헷갈립니다. 상세 조회는 이제
`patrol_logs`만 다룹니다 — 감지 요약과 원본 로그는 같은 테이블을 다른 해상도로 보는
것이라 한 자리에 묶이지만, 대응안은 테이블도 성격도 다릅니다.

**5. 기록 화면의 필터는 상세 조회와 따로입니다** (`plan_zone` / `plan_span`).
로그를 A 구역으로 좁혀 놓았다고 기록 화면까지 A 구역으로 열리면, 들어가자마자
"기록이 없다"를 보고 필터가 걸린 줄 모르게 됩니다.

### 갱신 주기

| 영역 | 주기 | 쿼리 |
|---|---|---|
| 경보 + 구역 카드 + 상태 바 | `REFRESH_STATUS_SECONDS` 1.0초 | 2개 |
| AI 권장 조치 (최신 1건) | `REFRESH_PLAN_SECONDS` 2.0초 | 1개 |
| 상세 조회 (감지 요약 / 원본 로그) | 선택한 범위에 따라 2.0 / 3.0 / 6.0초 | 1개 |
| AI 대응안 기록 화면 | 자동 갱신 없음 | 1개 |

상세 조회 주기는 `DETAIL_SPANS`가 정합니다(위 v9 표 참고). 현재 주기는 사이드바
캡션에 표시됩니다.

예전에는 두 영역이 각각 0.5초라 초당 6번 질의했습니다(2쿼리+1쿼리 × 2회/초).
사람이 화면 변화를 알아차리고 반응하는 데 최소 1초는 걸리므로 1초와 0.5초는 체감
차이가 없는데, DB 부하는 절반이 됩니다(**초당 약 3.2회**). 브라우저 탭 수만큼 곱해지는
값이라 시연 때 여러 대를 띄우면 차이가 커집니다.

사이드바의 **자동 갱신** 체크박스를 끄면 화면이 멈춥니다. 로그를 천천히 읽거나 화면을
캡처할 때 쓰세요(조각은 그대로 두고 `run_every`만 빼므로, 다시 켜면 이어서 돕니다).

## 핵심 구조

- **`get_db_connection()`** (`@st.cache_resource`): 앱 생명주기 동안 재사용되는 커넥션.
  연결 실패 시 예외를 그대로 올립니다 — 여기서 잡아서 `None`/`False`를 반환하면 그 실패
  결과 자체가 캐싱되어 DB가 나중에 살아나도 앱이 영구히 "실패" 상태로 남는 버그가 있었기
  때문입니다(v2에서 발견, v3에서 수정).
- **`init_db()`** (`@st.cache_resource`): `common.schema.init_all_tables()`를 호출해
  `patrol_zones`/`patrol_logs`/`response_plans`/`detection_events` 테이블을 준비합니다.
  이 대시보드는 자체 `CREATE TABLE` 문을 갖지 않습니다 — pipeline/integration 어댑터와
  스키마가 어긋나는(drift) 일을 막기 위해 v4에서 `common/schema.py`로 DDL을 이전했습니다.
  **데이터는 지우지 않습니다**(이유는 [`../admin/README.md`](../admin/README.md) 참고).
- **`get_cursor()`** (contextmanager): `RealDictCursor`로 매번 새 커서를 열고 `try/finally`로
  반드시 닫습니다. 커넥션이 끊긴 것을 감지하면 `get_db_connection.clear()`로 캐시를
  비워 다음 rerun에 새로 연결되게 합니다 — `@st.cache_resource`는 죽은 커넥션 객체도
  계속 돌려주므로, 이게 없으면 DB가 되살아나도 앱은 재시작 전까지 영구히 실패합니다.
- **`fetch_summary()`**: 최근 `RECENT_ALERT_MINUTES=5`분 이내 "위험" 건수, DB 현재 시각,
  구역별 최신 상태를 조회.
- **`fetch_log_summary(zone, span)`**: 연속 구간으로 접은 감지 요약 (v8에서 추가, 아래 참고).
- **`fetch_raw_logs(zone, span)`**: 프레임 단위 원본 `RAW_LOG_LIMIT=60`건.
- **`fetch_plans(limit, zone, minutes, prioritize)`**: `response_plans` 조회 (v7에서
  추가, v8에서 구역 필터와 `age_seconds`, v11에서 분 단위 기간과 우선순위 정렬).
  - `minutes=None`이면 시간 제한 없음 — 영상 옆 패널이 이 경로입니다. 마지막
    대응안이 20분 전 것이라도 그게 최신이라는 사실 자체가 정보이고, 범위를 걸어
    비워버리면 "대응안이 없다"로 잘못 읽힙니다.
  - `prioritize=True`면 신선한 것 안에서만 심각도로 줄을 세웁니다(위 v11 참고).
    기록 화면은 `False`(순수 최신순)입니다.
- **`_detail_filter(zone, minutes, time_column)`**: 구역과 시간 범위를 함께 거는
  `WHERE` 절. `patrol_logs` 조회 두 개가 공유합니다.
- **`_span(name)`**: 상세 조회 범위 이름 → `{minutes, scan_rows, refresh}`.
- **`_acknowledge(danger_id)`**: 경보 확인 버튼의 `on_click` 콜백.
- **`_beep_data_uri()` / `_play_alarm(nonce)`**: 코드에서 구운 경보음과 재생.
- **`_expanded_panel()` / `_expand_link(panel)` / `_set_expand(panel)`**: 크게 보기와
  대응안 기록 화면의 전환. 상태는 쿼리 파라미터(`?expand=`)가 단일 출처입니다.
- **`_zone_style(row)`**: 구역 한 칸의 (CSS 클래스, 상태 문구)를 정합니다.
  `ACTIVE_THRESHOLD_SECONDS=10`초 이내 로그가 없으면 위험도와 무관하게 "미연결"입니다.
- **`_render_status()` / `_render_plan_panel()` / `_render_detail()`**: 자동 갱신되는
  화면 조각 3개. `_render_status()`는 조회 실패 시 `_render_status_unavailable()`로
  빠집니다.
- **`_render_plan_history()`**: 대응안 기록 화면. 제목·닫기·필터를 스스로 그리고
  자동 갱신은 걸지 않습니다.
- **`_ago(seconds)` / `_percent(value)`**: 상대 시각과 백분율. 둘 다 `None`뿐 아니라
  **`NaN`도** 받습니다 — NULL이 한 행이라도 섞이면 pandas가 컬럼을 float으로 만들면서
  `None`을 `NaN`으로 바꿔놓기 때문입니다. `float(nan)`은 예외를 던지지 않으므로
  `_percent()`는 "NaN은 자기 자신과 같지 않다"로 걸러야 합니다(`try/except`로는 안 됩니다).
- **`_full_width_kwargs()`**: `st.dataframe`을 본문 폭에 맞추는 인자를 Streamlit 버전에
  맞춰 고릅니다 — 1.49 이상이면 `width="stretch"`, 그 아래면 `use_container_width=True`.
- **`_show_table(df)`**: NULL을 `-`로 채우고, 위험도에 따라 행 배경을 칠해 그립니다.
  Styler가 실패하면 조용히 평면 표로 떨어집니다.
- **`auto(fn, seconds)`**: 자동 갱신이 켜져 있으면 `st.fragment(run_every=)`로,
  꺼져 있으면 정지 조각으로 감쌉니다. `st.fragment`가 없는 구버전에서는 함수를 그대로
  돌려주고 스크립트 끝의 `time.sleep` + `st.rerun()` fallback이 갱신을 담당합니다.

### 구역/보기 선택 위젯이 조각 "바깥"에 있는 이유

`st.radio`를 자동 갱신되는 조각 안에 넣으면 갱신 때마다 위젯이 다시 그려져서 선택이
흔들립니다. `key=`로 `session_state`에 바로 묶어 두고, 조각 안에서는 값만 읽습니다.
(같은 이유로 `st.tabs` 대신 `st.radio`를 씁니다 — 탭 선택 상태는 Streamlit 버전에 따라
rerun에서 초기화될 수 있습니다.)

### HTML을 직접 그리는 곳의 이스케이프

구역 카드와 대응안 카드는 `unsafe_allow_html=True`로 그립니다. 여기에 들어가는
`detected_object`, `recommended_action`, `reference_docs`는 **DB(그리고 LLM)에서 온
문자열**이므로 예외 없이 `html.escape()`를 거칩니다. 구역 코드(`A`/`B`/`C`)와 상태 문구는
코드 안의 상수라 DB 값을 쓰지 않습니다.
[`../self_test/test_dashboard_layout.py`](../self_test/test_dashboard_layout.py)가
`<img src=x onerror=...>`와 `</div><script>...`를 미끼로 넣어 이 이스케이프가 실제로
동작하는지 확인합니다.

## 조회 성능 — 1초마다 도는 쿼리라 중요합니다

젯슨이 30fps로 추론하므로 `patrol_logs`는 매우 빠르게 커집니다. 세 가지를 손봤습니다.

**1. 구역별 최신 1건 — 윈도우 함수 → `DISTINCT ON`**

```sql
-- 이전: patrol_logs 전체를 읽고 정렬해야 함 (행 수에 비례해 느려짐)
SELECT ... FROM (SELECT ..., ROW_NUMBER() OVER (PARTITION BY zone ORDER BY log_time DESC) rn
                 FROM patrol_logs) t WHERE rn = 1

-- 현재: idx_patrol_logs_zone_time 을 타고 구역마다 첫 행만 집음
SELECT DISTINCT ON (zone) zone, risk_level, detected_object, log_time,
       EXTRACT(EPOCH FROM (LOCALTIMESTAMP - log_time)) AS age_seconds
FROM patrol_logs ORDER BY zone, log_time DESC
```

**2. 시각 기준을 DB로 통일**

예전에는 파이썬의 `datetime.now()`로 만든 값을 넘겨 비교했습니다. 대시보드 PC와 DB
서버가 다른 기기이거나 시간대가 다르면 "미연결" 판정과 "최근 5분" 집계가 통째로
어긋납니다. 이제 `LOCALTIMESTAMP` 기준으로 DB가 `age_seconds`까지 계산해 내려줍니다.
상태 바에 찍히는 **DB 시각**도 같은 쿼리에서 옵니다 — 그 시각이 흐르고 있다는 것 자체가
DB 왕복이 살아 있다는 증거라서, 화면이 멈춘 건지 조용한 건지 구분됩니다.

**3. `autocommit = True`**

이 대시보드는 조회만 하는데 psycopg2 기본값(`autocommit=False`)에서는 SELECT마다
트랜잭션이 열리고 커밋되지 않아 커넥션이 `idle in transaction` 상태로 남습니다.
그러면 그 시점 이후의 죽은 행을 VACUUM이 회수하지 못해, 초당 수십 건씩 쌓이는
`patrol_logs`가 급격히 비대해집니다. (관리 CLI의 `TRUNCATE`가 락을 못 잡고 멈추는
문제도 함께 해결됩니다.)

**4. 감지 요약 — gaps-and-islands (v8)**

구역 안에서의 순번에서 (구역, 객체, 위험도)별 순번을 빼면, 연속으로 이어지는 같은
조합끼리 같은 값(`grp`)을 갖습니다. 그걸로 묶으면 30fps짜리 수백 행이 한 줄이 됩니다.

```sql
SELECT MIN(log_time), MAX(log_time), COUNT(*), zone, detected_object, risk_level,
       MIN(distance) FILTER (WHERE distance >= 0) AS min_distance,
       (array_agg(issue ORDER BY log_time DESC))[1] AS issue
FROM (
    SELECT ..., ROW_NUMBER() OVER (PARTITION BY zone ORDER BY log_time DESC, id DESC)
                - ROW_NUMBER() OVER (PARTITION BY zone, detected_object, risk_level
                                     ORDER BY log_time DESC, id DESC) AS grp
    FROM (SELECT ... FROM patrol_logs [WHERE zone = %s]
          ORDER BY log_time DESC LIMIT 2000) recent
) marked
GROUP BY grp, zone, detected_object, risk_level
ORDER BY MAX(log_time) DESC LIMIT 30
```

세 가지가 의도적입니다.

- **`issue`로는 묶지 않습니다.** `classify_risk()`가 만드는 문구에 거리가 박혀 있어서
  (`"차량 근접 위험 (1.20m)"`) 매 프레임 문자열이 달라집니다. 그걸로 묶으면 구간이
  프레임 단위로 잘게 쪼개져 압축이 통째로 무의미해집니다. 대신 구간 안에서 가장 최근
  행의 `issue`를 대표로 씁니다.
- **두 순번 모두 `zone`으로 partition 합니다.** `전체`를 보면 여러 구역의 로그가
  시간순으로 섞여 들어오는데, 구역을 빼고 세면 A 구역의 연속 감지가 중간에 낀 B 구역
  로그 한 줄 때문에 두 구간으로 쪼개집니다.
- **`id DESC`는 윈도우 쪽에만 붙입니다.** 안쪽 `LIMIT`에 넣으면 인덱스
  `(zone, log_time DESC)`로 상위 N건만 집어오지 못하고 정렬이 생깁니다. 경계 한 줄이
  어느 쪽이 되든 결과에는 영향이 없습니다.

**5. `idx_patrol_logs_time` (v8에서 추가)**

`(zone, log_time DESC)` 복합 인덱스는 구역을 지정했을 때만 정렬에 쓸 수 있습니다.
상세 조회의 **기본값인 `전체`**는 `WHERE` 없이 `ORDER BY log_time DESC LIMIT N`을
돌리는데, 이때는 저 인덱스를 못 타서 `patrol_logs` 전체를 훑고 정렬합니다. 30fps로
쌓이는 테이블에서 2초마다 그러면 시연 도중 눈에 띄게 느려집니다.

인덱스는 `common/schema.py`의 `INDEX_DDL`이 `init_all_tables()`에서 함께 만듭니다.
`IF NOT EXISTS`라 기존 DB에 그대로 붙여도 됩니다 — 대시보드를 한 번 띄우면 생깁니다.

### 확인이 필요한 제약

- **소리 경보는 브라우저 자동재생 정책에 걸립니다.** 사이드바 체크박스를 켜는 동작이
  그 조건을 만족시키도록 설계했지만(기본값이 꺼짐인 이유), 브라우저·OS 설정에 따라
  첫 재생이 막힐 수 있습니다. 시연 전에 위험 이벤트를 한 번 흘려서 소리가 나는지
  확인하세요. 소리가 안 나도 화면 경보는 그대로 동작합니다.
- **조회 범위 30분은 최대 20,000행을 6초마다 집계합니다.** 브라우저 탭 수만큼
  곱해집니다. 여러 대를 띄우는 시연에서는 기본 5분을 권합니다.
- **영상 클릭 확대는 Streamlit의 HTML 정화기에 달려 있습니다.** `<a>`의
  `href`/`target`/`style`이 버전에 따라 걸러질 가능성이 있어, 같은 기능을 하는
  `⛶ 크게` 버튼을 함께 뒀습니다. 클릭이 안 되면 버튼을 쓰세요 — 기능은 동일합니다.
- **확대·복귀는 전체 rerun입니다**(쿼리 파라미터가 바뀌므로). 그 순간 영상 MJPEG이
  한 번 재연결됩니다. 의도한 사용자 조작이라 문제는 없지만, 연결에 1~2초 걸리는
  환경에서는 잠깐 자리표시자가 보일 수 있습니다.

- **구역 카드를 눌러 상세 조회로 연결되지 않습니다.** 카드는 HTML이라 그대로는
  클릭을 받을 수 없고, 카드 아래 버튼을 다는 것은 화면에서 가장 중요한 영역을
  어지럽힙니다. 얻는 것보다 잃는 것이 커 보여 보류했습니다.
- **경보 이력이 남지 않습니다.** 누가 언제 확인했는지는 세션 메모리에만 있고,
  브라우저를 새로 고치면 초기화됩니다. 교대 기록으로 쓰려면 테이블이 필요합니다.
