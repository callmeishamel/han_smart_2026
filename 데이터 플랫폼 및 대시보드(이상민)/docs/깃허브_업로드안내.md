# 깃허브 업로드 안내 — 대응안 생성 파트
---

### 섹션 1 — 지식베이스

```
rag/setup_knowledge_base.py
rag/sql/01_knowledge_base.sql
rag/sql/02_seed_data.sql
```

산업안전 지침을 저장할 테이블과 데이터입니다.
`safety_documents`(문서 원문)와 `safety_chunks`(절차 단위 청크) 두 개를
추가하며, 기존 테이블에는 영향을 주지 않습니다.

SQL 파일은 `setup_knowledge_base.py`가 같은 내용을 포함하고 있어
직접 실행하지 않아도 됩니다. DB 도구로 확인할 때 참고용입니다.

**커밋 메시지 예시**
`feat(rag): 산업안전 지식베이스 테이블 및 지침 데이터 추가`

---

### 섹션 2 — 대응안 생성기

```
integration/response_agent.py
```

`team_integration_adapter.py`의 `ResponseAgentAdapter` Protocol을
만족하는 실제 구현체입니다. `_MockResponseAgent`와 입출력 형태가 같아
교체만으로 연결됩니다.

지식베이스나 임베딩 모델이 없어도 내장 지침으로 동작하므로,
DB가 준비되지 않은 환경에서도 예외를 던지지 않습니다.

**커밋 메시지 예시**
`feat(integration): 대응안 생성 에이전트 구현`

---

### 섹션 3 — 실행 진입점

```
pipeline/patrol_pipeline_rag.py
run_pipeline_rag.sh
```

기존 `jetson_patrol_pipeline.py`의 `PatrolLogWriter`와
`iter_udp_detections`를 그대로 가져다 쓰고, 대응안 생성 단계만 얹었습니다.
적재 로직이 두 벌로 갈라지지 않도록 한 구성입니다.

`run_pipeline.sh`는 수정하지 않았습니다. 둘 중 하나만 실행하면 됩니다.

**커밋 메시지 예시**
`feat(pipeline): 대응안 생성 포함 파이프라인 및 실행 스크립트 추가`

---

### 섹션 4 — 검증

```
self_test/test_response_agent.py
```

DB와 네트워크 없이 실행되는 단독 테스트입니다. 50개 항목을 검증합니다.
반환 형식, 길이 제약, 위험유형 매핑, Mock 구현체와의 동일성,
비전 모듈 payload 경로를 확인합니다.

**커밋 메시지 예시**
`test: 대응안 생성기 단독 테스트 추가`

---

### 섹션 5 — 검색 고도화 (선택)

```
rag/embed_chunks.py
rag/vllm_client.py
```

임베딩 기반 유사도 검색과 경량 LLM 호출 부분입니다.
둘 다 선택 사항이며, 없어도 파이프라인은 동작합니다.

`embed_chunks.py`는 pgvector가 설치된 환경에서만 사용합니다.
`vllm_client.py`는 vLLM과 Ollama 모두 지원하며, 서버가 없으면
규칙 기반 생성으로 자동 대체됩니다.

**커밋 메시지 예시**
`feat(rag): 임베딩 적재 및 경량 LLM 호출 모듈 추가`

## 업로드 전 확인

`.gitignore`에 아래가 포함되어 있는지 확인하십시오.
`set_env.sh`는 이미 등록되어 있을 것입니다.

```
__pycache__/
*.pyc
set_env.sh
```

`rag/` 폴더에는 비밀번호나 접속 정보가 들어가지 않습니다.
DB 접속은 기존과 동일하게 `common/schema.py`의 `get_db_config()`를
통해 환경변수에서 읽습니다.

## 실행 권한

`run_pipeline_rag.sh`는 실행 권한이 필요합니다.
윈도우에서 커밋하면 권한이 빠질 수 있으므로, 저장소에 올린 뒤
아래를 한 번 실행해두면 다른 사람이 받을 때 권한이 유지됩니다.

```bash
git update-index --chmod=+x run_pipeline_rag.sh
```
