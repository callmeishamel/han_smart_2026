## 1. 요약

비전 모듈의 탐지 클래스가 변경되었으나 `classify_risk()`의 판정 정책이
갱신되지 않아, 현재 탐지되는 클래스 중 두 개가 미분류로 처리됩니다.

그 결과 **안전모 미착용 상황에서 대응안이 생성되지 않습니다.**
파이프라인이 위험 등급에서만 대응안 생성을 호출하기 때문입니다.

---

## 2. 현상

### 2.1 탐지 클래스 변경 내역

```
이전  ["fire", "hazardous leak", "obstacle", "human"]
현재  ["person with no helmet", "fire", "vehicle"]
```

### 2.2 현재 판정 정책

```python
ALWAYS_DANGER_OBJECTS  = {"fire", "hazardous leak"}
ALWAYS_CAUTION_OBJECTS = {"obstacle"}
# 거리 기반 판정 대상은 "human" 단일 문자열 비교
```

### 2.3 판정 결과

```python
classify_risk("person with no helmet", 1.1)
    -> ('주의', '미분류 객체 감지: person with no helmet')

classify_risk("vehicle", 1.3)
    -> ('주의', '미분류 객체 감지: vehicle')

classify_risk("fire", 3.5)
    -> ('위험', '화재 감지')                       # 정상 동작
```

현재 탐지 클래스 세 개 중 `fire`만 의도대로 판정됩니다.

또한 `OBJECT_KO_NAME`에도 현재 클래스가 없어, `detected_object`에
영문 문자열이 그대로 들어갑니다.

---

## 3. 영향

`pipeline/patrol_pipeline_rag.py`는 다음 조건에서만 대응안을 생성합니다.

```python
if event.risk_level != "위험":
    continue
```

따라서 안전모 미착용과 차량 근접 상황은 대응안 생성 대상에서 제외됩니다.
시연 시나리오가 안전모 미착용이라면 해당 기능이 동작하지 않습니다.

## 4. 제안 변경안 [적용 완료]

### 4.1 한글 표기 매핑 갱신

```python
OBJECT_KO_NAME = {
    # 현재 탐지 클래스
    "person with no helmet": "안전모 미착용",
    "fire":                  "화재",
    "vehicle":               "차량·중장비",
    # 과거 로그 조회를 위해 유지
    "hazardous leak":        "유해물질 누출",
    "obstacle":              "장애물",
    "human":                 "작업자",
}
```

### 4.2 판정 대상 집합 정의

안전모 미착용은 거리와 무관하게 규정 위반 상태이므로 항상 위험으로 둡니다.
차량은 작업자와 마찬가지로 거리 기반 판정이 적합합니다.

```python
ALWAYS_DANGER_OBJECTS  = {"fire", "hazardous leak", "person with no helmet"}
ALWAYS_CAUTION_OBJECTS = {"obstacle"}
DISTANCE_BASED_OBJECTS = {"human", "vehicle"}
```

### 4.3 판정 함수 변경

```python
def classify_risk(object_name: str, distance_m: float) -> tuple:
    """(object, distance) -> (risk_level, issue)."""
    ko_name = OBJECT_KO_NAME.get(object_name, object_name)

    if object_name in ALWAYS_DANGER_OBJECTS:
        return "위험", f"{ko_name} 감지"

    if object_name in ALWAYS_CAUTION_OBJECTS:
        return "주의", f"{ko_name} 감지"

    if object_name in DISTANCE_BASED_OBJECTS:
        if not is_distance_valid(distance_m):
            return "주의", f"{ko_name} 감지 (거리 미상)"
        if distance_m < HUMAN_DANGER_DISTANCE_M:
            return "위험", f"{ko_name} 근접 위험 ({distance_m}m)"
        if distance_m < HUMAN_CAUTION_DISTANCE_M:
            return "주의", f"{ko_name} 접근 관찰 필요 ({distance_m}m)"
        return "정상", ""

    return "주의", f"미분류 객체 감지: {object_name}"
```

### 4.4 변경 후 예상 결과

```python
classify_risk("person with no helmet", 1.1) -> ('위험', '안전모 미착용 감지')
classify_risk("vehicle", 1.3)               -> ('위험', '차량·중장비 근접 위험 (1.3m)')
classify_risk("vehicle", 2.5)               -> ('주의', '차량·중장비 접근 관찰 필요 (2.5m)')
classify_risk("vehicle", 8.0)               -> ('정상', '')
```

## 5. 부수 제안 — 거리값 유효성 검사

### 5.1 배경

`ai_inference_sender.py`의 거리 계산부는 시차를 구하지 못한 픽셀에
임시값을 대입합니다.

```python
disparity[disparity <= 0] = 0.1
depth_map = (focal_length * baseline) / disparity
```

이 경우 계산 결과는 다음과 같습니다.

```
500.0 * 0.06 / 0.1 = 300.0 (m)
```

300미터는 실내 공장 환경에서 성립하지 않는 값이지만, 현재 판정 로직은
`distance_m < 0` 조건만 검사하므로 유효한 거리로 통과합니다.

### 5.2 결과

실제로는 근접 상황인데 거리 계산이 실패한 경우 300미터로 기록되어
정상으로 분류됩니다. 위험 상황을 놓칠 수 있습니다.

### 5.3 제안 — 공통 스키마 측 방어 [적용 완료]

```python
MAX_VALID_DISTANCE_M = 15.0   # 실내 공장 기준 상한

def is_distance_valid(distance_m) -> bool:
    """시차 계산 실패값(-1.0, 300m 계열)을 배제합니다."""
    if distance_m is None:
        return False
    try:
        d = float(distance_m)
    except (TypeError, ValueError):
        return False
    return 0 <= d <= MAX_VALID_DISTANCE_M
```

숫자가 아닌 값이 들어와도 예외 없이 무효 처리하도록 `float()` 변환을 감쌌습니다.
`classify_risk()`의 거리 기반 분기가 이 함수를 통과한 값에만 적용됩니다.

### 5.4 근본 해결 — 비전 모듈 측 수정 [적용 완료]

시차를 구하지 못한 픽셀을 유효 깊이 계산 대상에서 제외합니다.
임시값 대입 대신 마스킹을 적용하는 방식입니다. `ai_inference_sender.py`에 반영했습니다.

```python
valid_disparity = disparity > 0
depth_map = np.full_like(disparity, -1.0)
depth_map[valid_disparity] = (focal_length * baseline) / disparity[valid_disparity]
```

5.4로 300m류 가짜값의 발생 자체를 막았고, 5.3의 `MAX_VALID_DISTANCE_M` 방어도
`common/schema.py`에 함께 적용했습니다. 비전 모듈 쪽 마스킹이 미래에 되돌아가거나
다른 센서가 붙어도 판정 로직이 이상치를 걸러냅니다.

## 6. 변경 시 영향 범위

| 대상 | 영향 |
|---|---|
| `patrol_logs` | `risk_level` 분포가 달라집니다 |
| 대시보드 | 강조 표시 대상 건수가 증가합니다 |
| 대응안 생성 | 호출 빈도가 증가합니다 |
| `self_test/test_schema_logic.py` | 기대값 갱신이 필요합니다 |

대응안 생성 호출이 늘어나는 점과 관련해, 동일 구역과 객체 조합에 대해
일정 시간 내 중복 생성을 억제하는 정책을 함께 검토하는 것을 제안합니다.
억제 간격은 60초를 기본으로 하되, 위험도가 상향되는 경우는 예외로 둡니다.

### 6.1 중복 억제 [적용 완료 — 간격 30초]

위 제안을 `common/schema.py`의 `ResponsePlanThrottle`로 구현하고
`pipeline/patrol_pipeline_rag.py`에 연결했습니다. **억제 간격은 팀 논의에 따라
60초가 아닌 30초를 기본값으로 적용**했습니다
(`RESPONSE_PLAN_SUPPRESS_SECONDS = 30.0`, 실행 시 `--suppress-seconds`로 변경 가능).

- 키: `(zone, detected_object)`
- 위험도 상향 시에는 간격과 무관하게 즉시 생성 (제안대로 예외 유지)
- `patrol_logs` 적재는 억제하지 않으므로 시계열 기록은 그대로 남음
- 검증: `python self_test/test_response_throttle.py`

4.2~4.3의 판정 정책 변경도 적용되었으므로, 억제 정책은 이제 `fire`뿐 아니라
안전모 미착용·차량 근접 상황에도 실제로 작동합니다. 억제가 없었다면 30fps로
들어오는 안전모 미착용 이벤트마다 대응안이 생성됐을 것이므로, 두 변경은 함께
적용되어야 의미가 있습니다.

### 7.1 DB에 이미 쌓인 로그

이 변경은 **앞으로 들어오는 이벤트**에만 적용됩니다. 적용 전에 `patrol_logs`에
`"주의" / "미분류 객체 감지: person with no helmet"`으로 적재된 행은 그대로
남아 있습니다. 시연 전에 정리하려면 해당 구간을 지우거나, 아래처럼 재분류하세요.

```sql
UPDATE patrol_logs
   SET risk_level = '위험',
       detected_object = '안전모 미착용',
       issue = '안전모 미착용 감지'
 WHERE issue LIKE '%person with no helmet%';
```
