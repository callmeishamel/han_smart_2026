# 시작하기

RAG 대응안 생성 파트를 이 PC 에서 돌리기 위한 절차입니다. 이 문서 한 장이면
됩니다. 막힐 때만 `설치가이드_리눅스.md` 를 보십시오.

탐지 이벤트가 들어오면 위험 등급인 경우에 산업안전 지침을 근거로 대응
지침을 만들어 DB 에 함께 저장하는 파트입니다.

---

## 1. DB 접속 정보

```bash
cd rag_upload
cp set_env.example.sh set_env.sh
nano set_env.sh
```

`SFP_DB_PASSWORD` 와 `SFP_DB_HOST` 를 채우십시오. 이 파일은 비밀번호가
들어가므로 git 에 올라가지 않습니다.

```bash
source set_env.sh
```

## 2. 설치

```bash
./setup_linux.sh --check     # 무엇이 빠졌는지만 확인
./setup_linux.sh             # 빠진 것만 설치
```

Python 패키지, Ollama, `gemma2:2b`, pgvector 를 확인하고 없는 것만
설치합니다. 단계마다 물어보며, 이미 되어 있으면 건너뜁니다. 여러 번
실행해도 안전합니다.

`sudo` 를 묻는 단계가 있습니다. pgvector 는 PostgreSQL 서버 확장이라
소스 빌드가 필요하고, Ollama 는 systemd 서비스로 등록됩니다.

## 3. 지식베이스 적재 (한 번만)

```bash
python3 rag/setup_knowledge_base.py
```

산업안전 지침 19건이 들어갑니다. 두 번 실행해도 중복되지 않습니다.

**여기까지가 필수입니다.** 아래 4번은 품질을 올리는 단계이고, 안 해도
대응안은 생성됩니다.

## 4. 품질 올리기 (선택)

```bash
python3 rag/check_pgvector.py          # 벡터 컬럼·인덱스 자동 추가
python3 rag/embed_chunks.py --search   # BGE-M3 약 2GB 자동 내려받음
python3 rag/check_llm.py               # LLM 서버 확인
```

## 5. 실행

```bash
./run_pipeline_rag.sh                          기본
./run_pipeline_rag.sh --use-llm --async-llm    LLM 사용
```

`--use-llm` 을 쓸 때는 `--async-llm` 을 **함께** 켜십시오. LLM 생성이 끝날
때까지 UDP 수신이 멈추는데, CPU 추론은 한 건에 수십 초가 걸려 그 사이
탐지 패킷이 유실됩니다.

---

## 잘 됐는지 확인

정상 로그는 이렇습니다.

```
[INFO] 적재 완료 [A] 화재 (위험도: 위험, 거리: 3.5m)
[INFO] 대응 지침 생성 [A] 확신도 0.60 | 근거 3건 (누적 1건)
```

`적재 완료` 만 뜨는 건 정상입니다. 위험 등급이 아닌 이벤트입니다.

확신도로 어느 경로가 동작 중인지 알 수 있습니다.

| 확신도 | 상태 |
|---|---|
| 0.75~0.95 | 벡터 검색 + LLM 생성 (전부 설치됨) |
| 0.70~0.95 | 벡터 검색 + 규칙 기반 문장 |
| 0.60 | 위험유형 조회 + 규칙 기반 문장 |
| 0.40 | DB 연결 안 됨. 코드 내장 지침으로 동작 중 |

**0.40 이 계속 나오면 DB 접속을 확인하십시오.** 파이프라인은 멈추지 않고
계속 돌기 때문에 눈에 잘 띄지 않습니다.

## 자주 막히는 것

**탐지 이벤트가 하나도 안 들어옴**
포트를 확인하십시오. 이 파이프라인은 **9998** 입니다. 9999 는 ROS2
브릿지가 쓰고 있어서 같은 포트를 잡으면 한쪽만 받습니다.

```bash
python3 pipeline/patrol_pipeline_rag.py --help | grep udp-port
```

**LLM 을 켠 뒤 탐지 로그가 띄엄띄엄 찍힘**
`--async-llm` 을 함께 켜십시오. 5번 참조.

**`pip install pgvector` 를 했는데 벡터 검색이 안 켜짐**
파이썬 패키지와 PostgreSQL 서버 확장은 다른 물건입니다. 확장은 DB 가
도는 PC 에서 설치해야 합니다. `./setup_linux.sh` 가 해 줍니다.

**LLM 응답이 안 옴**
CPU 추론은 첫 요청이 특히 느립니다.

```bash
export LLM_TIMEOUT=180
```

**`SFP_DB_PASSWORD가 비어 있습니다`**
`source set_env.sh` 를 먼저 실행하십시오. 터미널을 새로 열 때마다
필요합니다.
